xewe-os 3.0.1

xewe-os is the firmware template of XeWe OS for ESP32-C3, C6 and S3: a sketch, Config.h,
xewe.toml and two example modules. ./setup.sh installs the tools, XeWeCore, the modules and the
toolchain; `xewe` builds, flashes, provisions and tests. 3.0.1 brings the template up to XeWeCore
3.1.0 and xewe-os-tools 3.1.2 and adopts the unified configuration scheme (the core's
doc/config.md). The modules stay at 3.0.0; the template selects none.

CHANGED SINCE 3.0.0

- Config.h follows doc/config.md: no include, no build macros, a core block (XEWE_CORE_* values)
  and one block per selected module between marker lines. First-boot values are shipped commented
  out; uncomment one to pre-answer its question, or set it to INJECTED_FROM_DOTENV to take the
  value from the dotenv file at build time (`xewe build --env FILE`).
- The sketch includes Config.h before <XeWeCore.h> and declares `XeWeOs os({.url = ...})`: the
  device name, version, timestamp and serial settings come from Config.h and the build.
- The example modules keep their values in their own src/<Folder>/Config.h, in the module form of
  doc/config.md with the prefix XEWE_<ID>_ (XEWE_YOUR_MODULE_*, XEWE_YOUR_MOD_FULL_*). The
  heartbeat of YourModule is off by default; the starting level of YourModuleFull is a first-boot
  value.
- scripts/release.sh refuses an active INJECTED_FROM_DOTENV line before the card run and prints the
  tools ref that ci.yml uses. A unit test guards the shape of Config.h.
- Refs: core 3.1.0, tools 3.1.2 (ci.yml and xewe.toml name the same tag), modules 3.0.0,
  ArduinoJson v7.4.3. The release card replaces the hand-written test card.

BREAKING

- PROJECT_NAME, BUILD_VERSION, BUILD_TIMESTAMP, BUILD_CHIP, PROJECT_URL and SERIAL_BAUD_RATE are
  gone from Config.h, and the tools no longer generate PROJECT_NAME. A project made from 3.0.0
  takes the new Config.h and the new sketch line; its own values move into the core block.
- XEWE_DEVICE_NAME is XEWE_CORE_DEVICE_NAME. The dotenv keys the tools read are
  XEWE_CORE_DEVICE_NAME, XEWE_WIFI_SSID, XEWE_WIFI_PSW and XEWE_TIME_TZ_GMT_STR.
- The example modules no longer take a config struct from the sketch.

IMAGES

- One merged image per chip (c3, c6, s3), written at 0x0, with its meta.json and ESP Web Tools
  manifest.json: GitHub Release assets of this release. The template as it is, no modules selected.

NOT VERIFIED

- The C6 and S3 images were compiled, not run on a board.

TESTING

What was tested, on which tree and with which result: release_card.md, generated by
scripts/release.sh --prepare 3.0.1 and attached to this release. Board tests ran on an ESP32-C3.
